# 非功能需求与约束 — 优惠券发放与核销中心

需求基线来源：`../plan/req-plan.md`。

## 一、非功能需求

### NFR-001 并发正确性：库存不可超发

- **要求**：任意并发强度下 `claimed_count <= total_stock` 恒成立，且成功领取的券数严格等于 `claimed_count`。
- **实现约束**：条件 UPDATE（`WHERE claimed_count < total_stock`）+ 唯一索引 `UNIQUE(campaign_id, user_id, seq)`，全部并发控制交由 PostgreSQL，**应用层不实现任何锁、队列或串行化机制**（D-03）。
- **已知取舍**：单活动领取吞吐上限为 `campaign` 单行的更新速率，因所有并发领取排在同一行的行锁上。项目无 TPS 指标，已接受。
- **验证方式**：FR-070 并发脚本，N=100 与 N=1 各执行一次。
- **关联**：FR-010、INV-1

### NFR-002 幂等性

- **要求**：核销接口对同一券码的重复请求返回一致结果；风险标记处理接口重复调用返回当前状态。
- **实现约束**：幂等由券的状态机保证，不引入幂等键表（D-04）。
- **验证方式**：同一券码连续核销 4 次，响应体逐字节比对（首次成功响应除外）；同一券码并发 20 次核销。
- **关联**：FR-020、FR-052

### NFR-003 AI 调用的超时、重试与降级

- **要求**：AI 不可用时系统功能不缺失，仅降级。
- **实现约束**：推荐 3s 超时 / 最多重试 1 次；风控灰区 2s 超时 / 不重试。任一失败信号（超时、网络、凭证失效、非 2xx、非法 JSON、字段缺失、ID 不在白名单）均触发降级。
- **硬性要求**：**断网或凭证失效状态下，竞赛演示六步必须全部可完整走通**。降级路径是必交付功能（初始需求 6 明文要求），不是可选保险。
- **验证方式**：置无效凭证与断网两种场景下各跑一遍 SC-001 ~ SC-006。
- **关联**：FR-041、FR-051、FR-042

### NFR-004 凭证与数据安全

- **要求**：
  - Bedrock 凭证仅从环境变量读取，**不得出现在**仓库、日志、错误响应、`ai_invocation` 表、前端、演示截图中
  - `.env` 必须在 `.gitignore` 中
  - 用户只能访问自己的券（FR-011），越权返回 403 且不泄露资源存在性（FR-061）
  - 券码不可预测（NFR-006）
- **已知事项**：当前 token 曾在协作对话中明文出现，视为已泄露，须重新生成。
- **验证方式**：全仓库检索凭证特征串（`bedrock-api-key-`、`ASIA`）；越权用例；日志抽查。
- **关联**：FR-042、FR-061、CON-002

### NFR-005 时间与时区

- **要求**：全部时间字段以 UTC 存储（`timestamptz`），仅在展示层转换本地时区。
- **理由**：过期判定是核心业务规则，时区处理含糊会导致"这张券是否过期"无人说得清，且该类缺陷只在跨时区或夏令时暴露，演示时看不出来但代码评审一眼可见。
- **验证方式**：切换容器时区后过期判定结果不变。
- **关联**：FR-020、FR-011、D-16

### NFR-006 券码不可预测性

- **要求**：券码由密码学安全随机源生成，熵不低于 45 位，无可推导结构。
- **理由**：核销仅凭券码、不校验归属（D-12）。若券码可预测，等价于任意人可枚举并批量核销他人券。
- **验证方式**：生成 10000 个券码检查唯一性与字符集；人工审查生成逻辑不含 ID/时间戳。
- **关联**：FR-014、FR-020

### NFR-007 部署与可移植性

- **要求**：单机部署，`docker compose up` 一条命令起全套；缺少 AI 凭证时服务仍可启动并降级运行。
- **验证方式**：全新环境从零执行一次完整演示。
- **关联**：FR-071、CON-001、ASM-001

### NFR-008 可追溯性

- **要求**：每次 AI 调用与每次降级均落库（FR-053）；每次核销记录 `used_at` 与 `used_by`；每个风险标记记录判定依据与处理人。
- **理由**：AIDLC 设计门禁硬性要求 AI 可追溯与降级路径；且运营审核风险标记时若无判定理由则无法审核。
- **验证方式**：任取一条风险标记，能追溯到评分、依据、是否降级、处理人。
- **关联**：FR-053、FR-052、FR-020

### NFR-009 统计口径一致性

- **要求**：面板数字与数据库实时查询结果始终一致；两条对账恒等式（INV-1、INV-2）在任意时刻成立。
- **实现约束**：实时 SQL 聚合，禁止预聚合表与缓存层（避免双写导致面板与数据库打架）。
- **验证方式**：领券、核销、过期各若干笔后逐项核对恒等式。
- **关联**：FR-030、INV-1、INV-2

### NFR-010 可演示性

- **要求**：竞赛演示六步（SC-001 ~ SC-006）全部为系统真实行为，**不得依赖手工改库、预置脏数据或提前一天准备**。
- **实现约束**：`validity_minutes` 分钟粒度使"过期券核销"可现场自然构造（D-16）；风控硬阈值可配使拦截演示可控；并发脚本使不超发可当场验证。
- **验证方式**：完整演练一遍，全程不打开数据库客户端。
- **关联**：FR-070、D-16、D-08

### NFR-011 性能（演示级）

- **要求**：非 AI 接口 P95 < 300ms（本机）；推荐接口 P95 < 3.5s（含 AI）；降级路径 P95 < 500ms。
- **说明**：项目无生产级性能指标，本项仅用于识别明显退化。
- **验证方式**：演示流程中记录响应时间。

## 二、约束

### CON-001 单机部署
初始需求明确单机部署，不做多节点、不做水平扩展、不引入分布式组件。

### CON-002 AI 推理凭证
通过 API Token 调用 Amazon Bedrock。当前拿到的是**短期 key**（凭证 ID 以 `ASIA` 开头、带会话令牌、有效期 12 小时），region `us-east-1`。过期后替换环境变量即可，系统不实现自动续期。

### CON-003 业务范围排除
不含金额结算与支付对接（初始需求 4.8）。据此推论：核销不产生任何交易，因此核销由核销人员执行而非用户自助（D-12）。

### CON-004 技术栈
后端 Python + FastAPI + SQLAlchemy + Alembic；数据库 PostgreSQL；前端 React SPA（Vite + Tailwind + 组件库）；部署 docker compose。不引入 Redis、消息队列、定时调度器、Next.js。

### CON-005 无曝光埋点
系统不采集曝光数据，因此"领取率"的分母只能是库存总量，不能是曝光人数（D-10）。

### CON-006 用户历史数据贫瘠
系统无订单与支付数据，用户历史行为仅由领券与核销记录构成。AI 推荐的特征空间以此为限，并须处理零历史的冷启动（D-06）。

### CON-007 版本控制
项目根目录当前**未初始化 git**。进入实现阶段前须 `git init`，否则无法满足 AIDLC 对"保留用户改动、可回退"的要求。

## 五、运营增强 v2 非功能需求（2026-07-30，已确认）

### NFR-012 确定性风控与可解释性

- 同一输入特征、同一活动和同一策略版本必须产生完全相同的风险分与决策。
- 每次非放行决策必须保存因素贡献、证据快照、策略来源和策略版本；AI 仅生成解释，不得改变分数或决策。
- AI 不可用时模板解释须在非 AI 接口性能预算内返回。
- 关联：FR-054、FR-055、FR-057。

### NFR-013 增量兼容与不变量保持

- 运营增强必须通过新增 Alembic revision 实现，不修改历史迁移。
- 既有活动迁移后默认处于可运行、无限每日额度、全天可领、全部用户、继承中等风控的兼容状态。
- 现有 API 字段保持向后兼容；现有并发、领券、核销与演示脚本继续通过。
- 每日额度、人群与风控检查均不得破坏 INV-1、INV-2、INV-3。
- 关联：FR-004~007、FR-054~057。

### NFR-014 驾驶舱口径与刷新一致性

- 同一驾驶舱请求中的总览、趋势、提醒与活动列表必须使用同一个 `as_of` 时刻和过滤条件。
- 今天/每日额度/领取时段统一按 `Asia/Shanghai` 解释，持久化时间仍为 UTC。
- 自动刷新不得并发堆积；上一次请求未结束时不得启动下一次轮询。
- 趋势与总览值须可通过实时 SQL 对账，不建预聚合表或缓存层。
- 关联：FR-006、FR-032~034、NFR-009。

### NFR-015 配置变更审计

- 活动生命周期、投放策略、人群阈值、风控策略和提醒阈值的每次修改均记录修改人、时间、对象类型、对象 ID、修改前后 JSON。
- 审计日志只追加、不提供业务 API 删除或篡改能力；敏感凭证不得进入 JSON。
- 变更日志写入与配置变更处于同一数据库事务，避免“配置已变但无审计”。
- 关联：FR-004、FR-007、FR-055。

### CON-008 演示增强边界

本轮不引入 IP、设备指纹、外部短信/邮件/企业微信通知、自由规则编辑器、配置自动回滚、WebSocket、预聚合表、Redis、消息队列或定时调度器。非永久风险限制到期、活动时间状态和券过期均采用读取时惰性判断。
